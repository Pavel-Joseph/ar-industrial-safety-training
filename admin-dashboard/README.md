# Site Command — admin dashboard

React/Vite dashboard for the AR Industrial Safety Training Platform. It displays registered workers, validated AR training results, and QR-verifiable DGMS-aligned prototype certificates. The dashboard talks to the Node backend over HTTPS; it does not connect to PostgreSQL directly.

## Run locally against the hosted backend

The ignored `.env.local` in this checkout points to `https://ar-industrial-safety-api.onrender.com`. To set up another checkout, copy `.env.example` to `.env.local`.

```powershell
cd admin-dashboard
npm ci
npm run dev
```

Open **http://localhost:5173**. Sign in using the deployed backend's `DEMO_ADMIN_EMAIL` and `DEMO_ADMIN_PASSWORD` values. The sample account (`admin@site.local` / `admin123`) only works when `VITE_API_BASE_URL` is unset. Restart Vite after changing `.env.local`.

The Render backend's production `CORS_ORIGIN` is `https://ar-industrial-safety-training.vercel.app`. If the dashboard origin changes, update `CORS_ORIGIN` in the Render service/Blueprint and redeploy the backend. Browser CORS applies to dashboard requests even when the API URL works in Postman. For local dashboard development, temporarily allow `http://localhost:5173` in the backend configuration.

For production, `PUBLIC_BASE_URL` on Render must also be the dashboard origin. It makes generated certificate QR codes point to the public dashboard route, such as `https://ar-industrial-safety-training.vercel.app/verify/<public-id>`. `vercel.json` rewrites direct verification links to the React app, so scans and fresh browser tabs work without signing in.

The URL in `VITE_API_BASE_URL` is public and bundled into client JavaScript; never put passwords, JWTs, or database URLs in a `VITE_` variable. Admin JWTs are obtained through login. HTTPS is required for a hosted dashboard and API.

## Current API contract

| Dashboard action | Backend route | Notes |
| --- | --- | --- |
| Sign in | `POST /api/auth/login` | Reads `data.accessToken` and `data.user` |
| List/add worker | `GET/POST /api/workers` | POST sends `employeeCode`, `fullName`, `preferredLanguage` |
| Worker detail | `GET /api/workers/:id` | The dashboard also requests that worker's results and certificates |
| Training modules | `GET /api/modules` | Fire, Gas, optional Jharkhand module |
| Assessed attempts | `GET /api/results` | Filters by `workerId`, `moduleId`, `passed` |
| Certificates | `GET /api/certificates` | Filters by `workerId`, `moduleId`, `status` |
| Public verification | `GET /api/verify/:publicId` | No admin token |

List endpoints return `{ data, meta: { total, limit, offset } }`. The dashboard fetches all pages and maps nested backend records in `src/api/client.js` and `src/api/mappers.js`. It computes overview totals from these lists; the backend has no `/api/summary` route.

The backend does not store a worker's site, so site-specific controls and labels are hidden in live mode. Server results only represent attempts already synced and validated; pending offline attempts remain on the device and cannot appear in dashboard totals until the Unity app syncs them. Certificate QR codes generated by the backend open its own public `/verify/:publicId` page. The dashboard's `/verify/:publicId` route uses the same public API for certificates opened from its table.

With no `VITE_API_BASE_URL`, the dashboard uses in-memory sample data for demos. With a configured URL, connection or authorization errors remain visible; the UI never silently substitutes sample records for live data.

## Checks

```powershell
npm test
npm run build
```

After starting the dashboard, sign in and check Workers, Results, Certificates, one worker detail, and certificate verification. To confirm the browser connection, inspect the Network panel for requests to `https://ar-industrial-safety-api.onrender.com/api/...` and successful responses. The certificate language is **DGMS-aligned**; these are not official DGMS certificates.
