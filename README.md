# AR Industrial Safety Training

The Unity fire response lesson is in [`mobile-ar/Assets/Scenes/FireTraining.unity`](mobile-ar/Assets/Scenes/FireTraining.unity). Open `mobile-ar` in Unity 6000.3.0f1 and load that scene. It is enabled in the Unity build settings.

## Fire response lesson

1. Tap the visible floor immediately. Placement prefers a confirmed AR floor, accepts ARCore estimated planes or feature points while tracking warms up, and uses a stable camera based floor estimate as the final fallback. The visible training board stays hidden.
2. Turn around to inspect the room. The extinguisher and exit appear immediately at room scale, then automatically snap to detected vertical planes when ARCore finds suitable walls.
3. Watch up to 42 fire patches expand in a repeatable spiral sized to the detected floor. Tap the yellow aim target, then hold **Spray** and drag the extinguisher around the fire. Only flames inside the moving suppression radius lose heat; uncovered flames remain active and recover after an incomplete attempt.
4. Start evacuation and tap the exit door followed by the blue assembly point.

The progress panel tracks each stage. A completed run shows a versioned score, mistakes, total time, evacuation time, and sync status. Every correct and incorrect action is recorded in order with elapsed time. **Restart Training** starts a fresh attempt ID and placement. This is a training simulation; follow actual site emergency procedures in a real incident.

The portrait interface follows the supplied Figma reference: dark green camera overlays, peach primary controls, step cards, a live fire remaining meter, an extinguished confirmation, evacuation guidance, results, and an in-app help guide. It is generated by `FireTrainingUIController.cs` at runtime and scales from the Canvas reference resolution of 1080 × 1920.

The Fire score starts at 100 and loses 10 points for each incorrect selection. A complete ordered attempt passes at 70 or more. Results and pending uploads persist in Unity `PlayerPrefs` across app restarts. The API accepts duplicate retries for the same attempt ID only once. It validates action order and score before storing the attempt. No certificate is issued by this Fire prototype.

### Fire result API

Run `node backend/server.js` on a computer reachable by the test phone. The server listens on port 3000 and stores attempts in `backend/data/attempts.json`. In Unity, select **XR Origin** in the FireTraining scene. On its **Fire Module Progress** component, set **Api Base Url** to that computer's reachable URL, such as `http://192.168.1.20:3000`, and set **Worker Id** for the demonstrator. Build the app after setting the URL. Leave the URL blank to run fully offline and retain completed attempts as pending. Use an HTTPS URL for deployment; local HTTP may require Android cleartext traffic configuration.

The API exposes `GET /health`, `POST /api/attempts`, and `GET /api/attempts/:attemptId`. It returns an acknowledgement containing the attempt ID. The phone marks the attempt synced only after that acknowledgement. Run `node --test backend/test/fire-attempt.test.js` for scoring, order, persistence, and duplicate retry checks.

Fire instruction keys are in [`FireText.cs`](mobile-ar/Assets/Scripts/FireText.cs). English is included; Hindi and Santali copy must be supplied and reviewed before those languages are presented to workers.

The scenario prefab uses the imported double door, extinguisher, and exit sign models in `mobile-ar/Assets/Art/FireTraining`. Source files and attribution are in [`third_party/fire_training/CREDITS.md`](third_party/fire_training/CREDITS.md).

## Gas leak and confined space lesson

The shared home screen also starts a Gas Leak module. Tap the floor to place a mobile-friendly industrial installation with a storage tank, pipe rack, flanges, animated leaking valve, expanding hazard zone, portable detector, barricades, buddy worker, emergency shutoff, mechanical ventilation and a safe assembly point. The ordered exercise covers hazard recognition, SCBA respirator/chemical glove/gas-detector selection, buddy verification, remote isolation, ventilation and evacuation. Detector readings, alarm frequency, leak audio, plume emission and hazard size respond to the trainee's actions. The module uses the same fast AR fallback placement, large phone touch regions, centered dark-green UI, scoring, mistakes, attempt timing, restart flow and local result persistence as the Fire module. Its latest result appears in the shared results view.

## Verification

The Unity C# scripts were compiled against the project's generated Unity references, and the Fire API tests pass. AR placement, model appearance, touch targets, app restart persistence, and phone-to-backend syncing still require a playthrough on an ARCore capable Android device.

For an installable development APK, use **Tools > Fire Training > Build Android Prototype** in the Unity editor. It writes `mobile-ar/Builds/FireTrainingPrototype.apk`. A command-line build is also available with `-executeMethod BuildFirePrototype.Build`. The automated build attempt in this environment stopped at Unity Licensing Client initialization before APK packaging; the scene and scripts compiled independently.
